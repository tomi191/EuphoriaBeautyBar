# Site Bot („онлайн асистент") — дизайн

Дата: 2026-08-30 · Статус: одобрен в разговор (собственикът поиска вътрешен бот без LLM и очаква тестван резултат)

## Цел

Guided „хостеса" бот на публичния сайт: помага на посетителя да намери услуга/цена, да запази час, да научи работно време/адрес/плащане и дали има свободни места под наем. **Без LLM** — детерминистичен: нулев разход на съобщение, нулеви халюцинации (чете живите данни), нулеви external зависимости.

## Не-цели

- Не „разбира" свободен разговор като LLM; при непокрит въпрос ескалира към телефон/Viber.
- Не пази история между сесии; не събира лични данни (GDPR-чист).
- Не се показва на /admin и /staff (pathname guard като SiteHeader).

## Архитектура (3 единици)

1. **`src/lib/bot/engine.ts`** — чиста функция `answerQuestion(message, ctx) → BotReply`. Нормализация (lowercase, латиница→кирилица транслит, синоними: „балеаж"→балаяж и др.), интенти с приоритет: greeting → booking → работно време → локация/паркинг → плащане → работа/наем → човек/контакт → търсене на услуга (default) → FAQ match → fallback ескалация. Търсенето на услуга е token-overlap скоринг върху име+група+категория от каталога + LANDING map (боядисване/кичури/балаяж/почистване/кола маска/вежди → техните страници). Никаква I/O — 100% тестваема.
2. **`src/app/api/bot/route.ts`** — POST {message}. Строи контекста от живите източници: `getServiceCatalog()` (цени), `getFaqItems()` (FAQ от админа), `rentalPositions` + `rental_open` (кариери). Вика engine-а, логва въпроса в `bot_queries` (fire-and-forget) и връща BotReply.
3. **`src/components/bot/site-bot.tsx`** — client widget: плаващ бутон долу вдясно, панел със съобщения + quick-reply chips + input. Отговорите рендират links като бутони. Стилът следва съществуващите токени (foreground/mint).

## Данни

- **Каталог/цени**: винаги live от БД (същият източник като ценоразписа) — ботът не може да „измисли" цена.
- **FAQ**: `faq` таблицата (админът я поддържа).
- **Кариери**: активните `rentalPositions` при `rental_open=true`; иначе честно „в момента няма" + линк /karieri.
- **Статично**: работно време/адрес/плащане от `siteConfig`.
- **`bot_queries`** (нова таблица: id, message, intent, matched, created_at): логва всичко за преглед — неотговорените въпроси са суров keyword research. Създава се с идемпотентен `CREATE TABLE IF NOT EXISTS` скрипт (db:push е счупен), + drizzle схема за typed insert.

## Грешки

- API недостъпен/DB грешка → widget показва ескалационното съобщение (телефон/Viber) — ботът никога не „виси".
- Логването никога не блокира отговора (try/catch, без await на пътя на отговора).

## Тестове

1. `scripts/test-bot-engine.ts` — локална батерия (~15 реални въпроса: „балеаж цена", „manikur", „работно време", „работа при вас", „кола маска колко струва", „здравей", безсмислица→fallback) с assertions по интент/линкове.
2. `scripts/journey-bot.mjs` — journey срещу prod API след deploy (договор: status 200 + очакван интент/линк за всяка заявка).
3. Browser click-through на живия сайт: отваряне на widget-а, реален въпрос, проверка на отговора и линка (крайното действие).

## Отхвърлени алтернативи

- **LLM бот** (OpenRouter): разход/съобщение, риск от измислени цени, а кредитите вече веднъж умряха (блог engine-ът).
- **Trained NLU (Rasa и др.)**: свръхинженерство за ~8 интента на салонен сайт.
